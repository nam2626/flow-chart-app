# Feature Specification: 프레젠테이션 별도 접속 링크

**Feature Branch**: `001-presentation-access-link`  
**Created**: 2026-02-19  
**Status**: Draft

## Clarifications

### Session 2026-02-19

- Q: 프레젠테이션 링크 접근 제어 방식을 어떻게 정의할까? → A: 링크 소지자는 접근 가능, 링크 재생성 시 기존 링크 즉시 무효화
- Q: 프레젠테이션 화면의 편집 반영 시점을 어떻게 정의할까? → A: 링크 접속 후에도 편집 저장이 발생하면 발표 화면에 실시간 자동 반영
- Q: 프레젠테이션 링크 식별자 형식은 무엇으로 할까? → A: 짧은 공유 코드(6~8자) 링크
- Q: 링크 재생성 시 이미 열려 있던 발표 탭 처리 방식은 무엇으로 할까? → A: 링크 재생성 즉시 기존 발표 탭도 접근 차단

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 프레젠테이션 전용 링크 진입 (Priority: P1)

발표자는 편집 화면과 분리된 프레젠테이션 전용 링크를 생성하고, 해당 링크로 전체화면 발표 화면에 직접 진입한다.

**Why this priority**: OBS와 같은 외부 도구는 명확한 URL이 있어야 소스를 안정적으로 등록할 수 있으므로, 별도 링크 제공이 핵심 가치다.

**Independent Test**: 사용자가 다이어그램에서 프레젠테이션 링크를 생성한 뒤 새 브라우저 창에서 해당 URL을 직접 열어 발표 화면에 즉시 진입하면 독립적으로 검증된다.

**Acceptance Scenarios**:

1. **Given** 사용자가 다이어그램을 편집 중이고 프레젠테이션 기능을 사용할 수 있는 상태에서, **When** 프레젠테이션 전용 링크 생성을 요청하면, **Then** 사용 가능한 고유 URL이 표시된다.
2. **Given** 생성된 프레젠테이션 전용 URL이 있을 때, **When** 사용자가 해당 URL을 브라우저 주소창에 입력하거나 OBS 브라우저 소스로 등록하면, **Then** 편집 UI 없이 발표 전용 화면이 열린다.

---

### User Story 2 - 링크 공유 및 재사용 (Priority: P2)

발표자는 생성된 프레젠테이션 전용 링크를 복사해 타 장치나 동료에게 전달하고 동일한 화면으로 재접속한다.

**Why this priority**: 실제 발표 환경은 다중 장치 전환이 잦아 링크 재사용 가능성이 운영 안정성에 직접 영향을 준다.

**Independent Test**: 링크를 복사해 다른 브라우저 또는 다른 장치에서 열었을 때 동일한 발표 화면이 재현되면 검증된다.

**Acceptance Scenarios**:

1. **Given** 사용자가 프레젠테이션 전용 링크를 생성한 상태에서, **When** 링크를 복사해 다른 환경에서 열면, **Then** 동일한 다이어그램 발표 화면이 표시된다.

---

### User Story 3 - 링크 접근 실패 안내 (Priority: P3)

사용자는 만료되었거나 유효하지 않은 프레젠테이션 링크에 접근할 때 이해 가능한 안내를 받는다.

**Why this priority**: 공유 링크 기반 기능은 실패 상황의 명확한 안내가 없으면 발표 중 장애 대응이 어렵다.

**Independent Test**: 잘못된 링크로 접속했을 때 안내 문구와 다음 행동(유효 링크 재생성)이 제시되면 검증된다.

**Acceptance Scenarios**:

1. **Given** 유효하지 않거나 삭제된 프레젠테이션 링크에 접근할 때, **When** 페이지를 열면, **Then** 접근 불가 사유와 복구 방법이 포함된 안내가 표시된다.

### Edge Cases

- 프레젠테이션 링크를 아직 생성하지 않은 문서에서 사용자가 직접 발표 URL 경로로 접근할 때는 생성 필요 안내를 보여준다.
- 링크 생성 후 원본 문서가 삭제되었거나 접근 권한이 변경된 경우에는 발표 화면 대신 접근 제한 안내를 보여준다.
- 네트워크 일시 장애로 발표 데이터 로딩이 실패하면 자동 재시도 또는 수동 새로고침 안내를 제공한다.
- 동일 링크를 여러 클라이언트가 동시에 열어도 발표 화면 진입 동작은 일관되어야 한다.
- 링크 재생성 이후 기존 URL로 접근하면 즉시 접근 거부 안내가 표시되어야 한다.
- 링크 재생성 이후 기존 URL로 이미 열려 있던 발표 탭도 즉시 접근 거부 상태로 전환되어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 각 다이어그램에 대해 프레젠테이션 전용 접근 URL을 생성할 수 있어야 한다.
- **FR-002**: 시스템은 생성된 프레젠테이션 URL을 사용자가 명확히 확인하고 복사할 수 있는 방식으로 제공해야 한다.
- **FR-003**: 시스템은 프레젠테이션 URL로 접근한 사용자에게 편집 기능이 없는 발표 전용 화면만 표시해야 한다.
- **FR-004**: 시스템은 프레젠테이션 URL로 접속한 이후에도 원본 문서에 새 저장이 발생하면 발표 화면에 최신 저장 상태를 자동 반영해야 한다.
- **FR-005**: 시스템은 유효하지 않거나 접근 불가능한 프레젠테이션 URL 요청에 대해 원인과 해결 방법이 포함된 오류 안내를 표시해야 한다.
- **FR-006**: 시스템은 사용자가 언제든지 기존 프레젠테이션 URL을 다시 확인할 수 있어야 하며, 문서 재접속 후에도 동일 링크를 재사용할 수 있어야 한다.
- **FR-007**: 시스템은 사용자가 원할 때 프레젠테이션 URL을 재생성(기존 링크 무효화)할 수 있어야 한다.
- **FR-008**: 시스템은 프레젠테이션 URL 접근 시 브라우저 탭 제목에 문서 식별 가능한 이름을 표시해야 한다.
- **FR-009**: 시스템은 로그인 여부와 무관하게 유효한 프레젠테이션 URL 소지자에게 발표 화면 접근을 허용해야 한다.
- **FR-010**: 시스템은 프레젠테이션 URL 식별자로 6~8자 길이의 공유 코드를 사용해야 하며, 해당 코드는 링크 재생성 시 새 값으로 교체되어야 한다.
- **FR-011**: 시스템은 링크 재생성 이벤트가 발생하면 기존 링크로 열려 있던 활성 발표 화면을 즉시 종료 또는 접근 거부 상태로 전환해야 한다.

### UX Consistency Requirements *(mandatory)*

- **UX-001**: 프레젠테이션 관련 용어(예: "프레젠테이션 링크", "링크 재생성")는 편집 화면과 발표 화면에서 동일하게 사용되어야 한다.
- **UX-002**: 링크 생성/복사/재생성 결과 피드백은 기존 앱의 토스트 또는 안내 패턴과 일관된 톤으로 제공되어야 한다.
- **UX-003**: 오류 안내에는 문제 원인과 다음 행동(재시도, 링크 재생성, 문서 이동)을 한 화면에서 확인할 수 있어야 한다.

### Performance Requirements *(mandatory)*

- **PRF-001**: 프레젠테이션 URL 접속 후 초기 발표 화면은 기준 측정 환경에서 95%의 경우 300ms 이내에 표시되어야 한다.
- **PRF-002**: 발표 화면 진입 실패율은 월간 기준 1% 미만이어야 한다.
- **PRF-003**: 동일 URL 반복 접속 시 첫 화면 표시 시간의 편차는 95% 구간에서 1초 이내여야 한다.

### Code Convention Requirements *(mandatory)*

- **CCR-001**: 사용자에게 노출되는 신규 문구는 기존 제품 용어 사전과 동일한 표현을 사용해야 한다.
- **CCR-002**: 신규 설정명과 사용자 액션명은 기존 기능과 충돌 없는 일관된 명명 규칙을 따라야 한다.
- **CCR-003**: 프레젠테이션 관련 문서화는 변경 이력과 사용자 영향 범위를 포함해야 한다.

### Key Entities *(include if feature involves data)*

- **프레젠테이션 링크**: 특정 다이어그램의 발표 전용 진입점을 나타내는 공유 가능한 식별자. 상태(활성/무효), 생성 시각, 연결 대상 문서 정보를 가진다.
- **공유 코드**: 프레젠테이션 링크에 포함되는 6~8자 길이의 식별 문자열. 활성 링크에서는 유일해야 하며 재생성 시 새 코드로 바뀐다.
- **발표 세션 화면**: 프레젠테이션 링크로 접근했을 때 제공되는 읽기 전용 표시 컨텍스트. 연결된 다이어그램 버전, 표시 상태, 오류 상태를 가진다.
- **링크 접근 이벤트**: 프레젠테이션 링크 접근 시도 결과를 나타내는 기록 단위. 성공/실패 유형과 발생 시각을 가진다.

### Assumptions

- 프레젠테이션 링크는 문서 단위로 1개 활성 링크를 기본값으로 제공한다.
- 링크를 아는 사용자는 별도 로그인 없이 발표 화면에 접근할 수 있다고 가정한다.
- 발표 화면은 기존 프레젠테이션 모드와 동일한 시각 구성을 유지한다.
- 발표 화면은 링크 접속 중에도 원본 문서의 저장 변경 사항을 자동으로 수신해 최신 상태를 유지한다.

### Dependencies

- 기존 프레젠테이션 모드 렌더링 동작이 안정적으로 유지되어야 한다.
- 문서 식별 이름이 일관되게 저장되어 있어야 브라우저 탭 제목에 반영할 수 있다.
- 링크 공유 대상 환경(OBS 브라우저 소스 포함)에서 표준 URL 로딩이 가능해야 한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자 테스트에서 95% 이상이 1분 이내에 프레젠테이션 전용 링크를 생성하고 복사할 수 있다.
- **SC-002**: OBS 브라우저 소스 등록 시도 중 95% 이상이 첫 시도에서 발표 화면 연결에 성공한다.
- **SC-003**: 유효하지 않은 링크 접근 시 100%의 사례에서 오류 원인과 다음 행동이 표시된다.
- **SC-004**: 배포 후 2주 내 "프레젠테이션 링크를 찾을 수 없음" 유형 지원 문의가 기존 대비 80% 이상 감소한다.
